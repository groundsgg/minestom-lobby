# Sound-aware NPC gesture admission

Continue the supplied Guildfolk update: a sounding gesture may not restart or overlap another gesture until both its animation and audio end. During that interval new one-shot requests are rejected, as in the vendor aura condition; do not queue bursts. Normal idle, explicit stop, transform/scale, hover, view cohorts and collision retain existing semantics. Explicit PlaySoundAction is a separate manual diagnostic outside gesture admission. No per-player/private cache or proxy-local identity assumption.

Root cause: Scene currently commits a new logical animation clock before calling renderer start. A renderer-only rejection corrupts later animation timing. Add optional Scene animation admission reservations. Reserve every active targeted handle before changing logical state or starting any handle; cancel all earlier leases on veto/failure and close all leases even when a close callback fails. Reservations block autonomous idle gestures and direct starts until consumed/closed. Return ordinary REJECTED for a veto. Existing renderers without the capability retain behavior and inactive targets still store logical animation.

Compiler extracts conservative ceil-ms duration once from bounded, checked single-stream Ogg Vorbis pages and emits it with each existing sound. Keep raw OGG bytes, authored animation lengths/curves and geometry unchanged. The private NPC sound model loads optional duration, default0 for old JSON; published four-argument constructor/copy/default-copy/components remain callable; duration is retained by copies. All deployed host/runtime classes are rebuilt together; no Maven publication in this work. Runtime gate uses monotonic time and max(animation duration, audio duration extended for slower source/event pitch (faster pitch conservatively keeps base duration), rounded up50ms plus100ms tail). No file decode or added timer task on the tick path. Auto idle2 goes through the same gate. Explicit visual stop retains the audible clip's remaining hold; close never emits more sounds. Looping idle can be restored without erasing a current audio hold.

Alternative renderer-only ignore was rejected because Scene would still reset authoritative state. Delaying actions in a queue was rejected because repeated clicks would produce stale greetings. Source admission is the smallest state-correct boundary. Test fake clock plus real packet/pose effects, Scene state rejection and multi-handle atomicity; import codec/length/CRC/truncation/multiplex/continuation bounds. Keep earlier performance candidate excluded, same accepted Lobby3657/Player/Minigame/map/CPU2/JVM1 pins. Prepare full private build before any publication/activation; native Java hearing/collision/scale test remains separate.

Sources for build-time timing metadata: [Xiph Vorbis I, sectionA.2](https://www.xiph.org/vorbis/doc/Vorbis_I_spec.html), [Ogg RFC3533, section6](https://www.rfc-editor.org/rfc/rfc3533). This reader checks container consistency and metadata; it does not decode Vorbis codebooks or audio samples.
